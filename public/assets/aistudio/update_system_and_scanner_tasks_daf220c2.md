# دفعة المهام الشاملة (Password Recovery, Cloudflare Migration, QR Scanner Sync & Visitation RBAC)

<project_context>
- **المشروع:** تطبيق ويب (`3fetyayouth.online`).
- **قاعدة البيانات والـ Backend:** Cloudflare Database (إلغاء أي ارتباط متبقٍ مع Supabase).
- **الأجزاء المستهدفة:** نظام استعادة كلمة المرور، تنظيف مسميات وارتباطات Supabase، الماسح الضوئي (QR Scanner) ومزامنة الحضور بين الخدام، ونظام الافتقاد وصلاحيات الرتب.
</project_context>

<tasks>
نفذ المهام الـ 5 التالية بالترتيب، وافصل بين حل كل مهمة بعنوان واضح (`## Task 1`, `## Task 2`...):

### Task 1: نظام استعادة كلمة المرور (البطاقة الشخصية / البصمة + زر تواصل مع الأدمن)
- **المطلوب بالتفصيل:**
  1. **إلغاء إرسال كلمة المرور القديمة واستبدال الزر:**
     - احذف نهائياً خاصية إرسال كلمة المرور القديمة عبر الواتساب، وامنع استرجاع الباسورد بالاسم ورقم الهاتف فقط.
     - استبدل زر إرسال الباسورد القديم بزر جديد باسم **`تواصل مع الادمن`** (يفتح محادثة واتساب مباشرة مع رقم الأدمن لطلب المساعدة بدون عرض أي كلمات سر في الرابط).
  2. **الاستعادة التلقائية عبر صورة البطاقة الشخصية (ID Card QR Verification):**
     - أضف في صفحة "نسيت كلمة المرور" زر **"تأكيد الهوية عبر صورة البطاقة الشخصية"** يسمح للعضو برفع صورة بطاقته من استوديو الهاتف أو مسحها بالكاميرا.
     - اقرأ الـ QR Code داخل المتصفح (Client-side)، وإذا تطابق التوكن/المعرف الخاص بالعضو، افتح له فوراً حقل **"تعيين كلمة مرور جديدة"** واحفظها في Cloudflare Database.
  3. **الاستعادة عبر بصمة الهاتف / مفتاح الجهاز (Device Trust / WebAuthn):**
     - اربط حساب العضو عند دخوله بـ `deviceRecoveryToken` مشفر في جهازه (أو بصمة الهاتف `WebAuthn`)، ليتمكن من تغيير كلمة المرور فوراً إذا كان يفتح من نفس هاتفه الموثوق.

### Task 2: إزالة كافة ارتباطات ومسميات Supabase وتوحيد المزامنة مع Cloudflare
- **المطلوب بالتفصيل:**
  1. **تغيير أسماء الملفات والمتغيرات:** أي ملف أو دالة أو متغير لا يزال يحمل اسم `supabase` (مثل `supabase.ts` أو `supabaseClient`) قم بتغيير اسمه ومراجع استيراده (`imports`) ليعكس `cloudflare` (مثل `cloudflareDb.ts` أو `cloudSync.ts`).
  2. **تعديل نص لوحة التحكم:** غيّر النص الظاهر في لوحة التحكم من:
     `مزامنة سحابية لحظية (supabase realtime live sync)`
     إلى:
     `مزامنة سحابية لحظية (Cloudflare Realtime Live Sync)`
  3. **فحص الاتصال الفعلي:** تأكد برمجياً من إلغاء أي اتصال أو مكتبة أو مفتاح API تابع لـ Supabase، وأن جميع عمليات القراءة والكتابة والمزامنة اللحظية تتم 100% عبر `Cloudflare`.

---

### Task 3: تنظيف واجهة الماسح الضوئي (إخفاء أزرار التجربة السريعة)
- **الجزء المستهدف:** صفحة/مكون الماسح الضوئي (QR Scanner) -> قسم التسجيل اليدوي بالحضور.
- **المطلوب بالتفصيل:**
  1. احذف/أخفِ تماماً العنوان **`ازرار سريعه لتجربة و تسجيل الحضور بنقره واحدة`** مع **جميع الأزرار السريعة** التابعة له من الواجهة والكود.

---

### Task 4: منع تكرار الحضور في الماسح الضوئي + نوافذ التنبيه (Alert Popups) + المزامنة المشتركة بين الخدام
- **الجزء المستهدف:** الماسح الضوئي (QR Scanner) وقائمة الحضور اليومية.
- **المطلوب بالتفصيل:**
  1. **منع تكرار الحضور لنفس الشخص في نفس اليوم:**
     - يُسمح بتسجيل حضور المخدوم **مرة واحدة فقط** في التاريخ الواحد.
  2. **نافذة التنبيه عند التسجيل لأول مرة (Success Alert Popup):**
     - عند مسح الـ QR Code (أو التسجيل) لأول مرة بنجاح، أظهر مربع نافذة منبثقة واضح (**Alert Popup Modal**) يحتوي على علامة صح خضراء والرسالة التالية (مع وضع اسم المخدوم الفعلي المربوط بالـ QR Code):
       `تم تسجيل الحضور لـ [اسم الشخص] بنجاح`
  3. **نافذة التنبيه عند التكرار للمرة الثانية (Duplicate Error Alert Popup):**
     - إذا حاول الخادم (أو أي خادم آخر) أخذ الحضور لنفس الشخص مرة ثانية في نفس اليوم، ارفض التكرار وأظهر مربع نافذة منبثقة (**Alert Popup Modal**) يحتوي على **علامة خطأ حمراء كبيرة (❌)** والرسالة التالية (مع وضع اسم المخدوم المربوط بالـ QR Code):
       `تم اخد الحضور لـ [اسم الشخص] مسبقاً`
  4. **مزامنة قائمة (جميع الاسماء المأخوذ لها حضور لهذا التاريخ) بين جميع الخدام:**
     - اربط قائمة `جميع الاسماء المأخوذ لها حضور لهذا التاريخ` بقاعدة بيانات Cloudflare مباشرة (Shared Global Attendance List for Today) مع تحديث لحظي (Polling / Realtime Sync).
     - إذا كان هناك أكثر من خادم يسجلون الحضور في نفس الوقت (مثلاً: `خادم 1` و`خادم 2`)، يجب أن تظهر لكل خادم **جميع الأسماء التي تم تسجيل حضورها اليوم بواسطة كل الخدام معاً** (المخدومون الذين سجلهم `خادم 1` يظهرون فوراً عند `خادم 2`، والمخدومون الذين سجلهم `خادم 2` يظهرون فوراً عند `خادم 1`).

---

### Task 5: تخصيص صلاحيات نظام الافتقاد لـ (أمين الخدمة) مع زر تحكم لدى (مسؤول المجتمع)
- **الجزء المستهدف:** نظام الافتقاد (Visitation System) وإدارة صلاحيات الرتب عند `مسؤول المجتمع` (Community Owner).
- **المطلوب بالتفصيل:**
  1. **الوضع الافتراضي لـ (أمين الخدمة) في الافتقاد:**
     - في نظام الافتقاد، يظهر لرتبة `أمين الخدمة` افتراضياً **فقط المخدومون المطابقون لجنسه** (الذكور للأمين الذكر، والإناث للأمينة الأنثى).
  2. **صلاحية التحكم عند (مسؤول المجتمع) في إعدادات الرتب:**
     - في لوحة تحكم `مسؤول المجتمع` (قسم صلاحيات الرتب)، أضف خيار تحكم (Toggle / Select) خاص بصلاحية `أمين الخدمة` يحفظ حالته في قاعدة البيانات (Cloudflare)، ويسمح لمسؤول المجتمع بالاختيار بين وضعين:
       - **الوضع الأول (الافتراضي):** إظهار المخدومين **من نفس جنسه فقط** لأمين الخدمة.
       - **الوضع الثاني (شامل):** إظهار **كل المخدومين (ذكور وإناث)** لأمين الخدمة.
     - ينعكس اختيار `مسؤول المجتمع` فوراً على ما يظهر لـ `أمين الخدمة` في نظام الافتقاد ولوحات المخدومين.
</tasks>
