# دفعة المهام اليومية (Data Persistence, State Sync, CMS Fix & IP Ban System)

<project_context>
- **المشروع:** تطبيق ويب (`3fetyayouth.online`).
- **قاعدة البيانات والـ Backend:** Cloudflare Database (D1 / Durable Objects / KV) مع مزامنة الواجهة الأمامية.
- **الأجزاء المستهدفة:** حفظ وتحديث بيانات الأعضاء، تاريخ آخر تحديث في البطاقة الشخصية، أداة تعديل نصوص الموقع (Live CMS)، زر الدعم الفني، ونظام الحظر الشامل (User + IP Ban).
- **الهدف العام:** القضاء نهائياً على مشاكل الـ State Race Conditions (تحول الأسماء إلى "عضو"، تذبذب التواريخ، ورجوع النصوص القديمة)، إصلاح تكرار وتصميم زر الدعم، وبناء نظام حظر متكامل بالـ IP مع إمكانية فك الحظر.
</project_context>

<tasks>
نفذ المهام الـ 5 التالية بالترتيب، وافصل بين حل كل مهمة بعنوان واضح (`## Task 1`, `## Task 2`...):

### Task 1: منع تحول اسم المسجل الجديد إلى كلمة "عضو" وربط التحديث بـ Cloudflare Database
- **المشكلة الحالية:** عند تسجيل شخص جديد، يظهر اسمه الحقيقي في البداية ثم يتحول فجأة إلى القيمة الافتراضية `"عضو"` سواء في صفحته أو في الداشبورد (بسبب دالة Fallback أو Sync تقوم بالكتابة فوق الاسم الحقيقي عند إعادة الجلب).
- **المطلوب بالتفصيل:**
  1. **منع الكتابة فوق البيانات (Prevent Fallback Overwrite):** ابحث في الكود عن أي مكان يعين قيمة افتراضية مثل `name || 'عضو'` أثناء الـ Hydration أو الـ Polling أو تحديث الجلسة، وامنع استبدال الاسم المسجل في قاعدة البيانات بالقيمة الافتراضية.
  2. **ثبات البيانات:** تأكد أن اسم المستخدم وجميع بياناته تظل ثابتة تماماً كما سجلها أول مرة، ولا تتغير إطلاقاً إلا إذا قام المستخدم نفسه بالضغط على خيار `تحديث بياناتي` من صفحته الشخصية.
  3. **مزامنة Cloudflare Database:** عند قيام المستخدم بتحديث بياناته عبر `تحديث بياناتي`، يتم إرسال التعديل وحفظه فوراً في `Cloudflare Database`، وينعكس التحديث مباشرة في جدول الداشبورد بدون أي تعارض.

---

### Task 2: إصلاح تذبذب ولاغ (Lag) تاريخ "تم تحديث البيانات" في البطاقة الشخصية
- **المشكلة الحالية:** في بطاقة مسؤول المجتمع (`ميخائيل ادور راتب`) وباقي البطاقات، يظهر إشعار/نص `تم تحديث البيانات 11/11/2026` بدون أن يقوم المستخدم بتحديث بياناته، ثم يتذبذب ويعود إلى `8/11/2026` (بسبب استخدام `new Date()` أثناء الرندرة أو تحديث حقل `updated_at` تلقائياً عند كل قراءة/تسجيل دخول).
- **المطلوب بالتفصيل:**
  1. **إيقاف التحديث الوهمي للتاريخ:** امنع الكود من تعديل حقل تاريخ آخر تحديث (`updatedAt` / `last_updated`) أثناء فتح الصفحة أو جلب البيانات أو فحص الجلسة.
  2. **ربط التاريخ بحدث التعديل الفعلي فقط:** لا يتم تغيير قيمة تاريخ التحديث إلا عند تنفيذ دالة `تحديث بياناتي` فعلياً وحفظها في قاعدة البيانات.
  3. **توحيد مصدر التاريخ:** اجعل البطاقة تقرأ تاريخ آخر تحديث مباشرة من الحقل المحفوظ في قاعدة البيانات (Single Source of Truth) ليثبت التاريخ الحقيقي لآخر تعديل بدون أي Lag أو تذبذب بين تاريخين.

---

### Task 3: حل جذري ونهائي لمشكلة أداة (تعديل نصوص الموقع) وتعميم التعديلات فوراً
- **المشكلة الحالية:** عند تعديل أي نص في (`لوحة التحكم`، `صفحة المخدومين`، `بوابة الدخول`، أو `تسجيل العضوية`) عبر أداة `تعديل نصوص الموقع`، إما لا يتغير النص، أو يتذبذب بين النص القديم والجديد (Flickering/Lag) لأن المكونات تعيد قراءة النصوص الأصلية المكتوبة داخل الكود (Hardcoded Defaults).
- **المطلوب بالتفصيل:**
  1. **عزل النصوص الافتراضية (Override Hardcoded Texts):** صمم طبقة قراءة النصوص (Text Provider / Custom Hook) بحيث تعطي الأولوية المطلقة للنص المحفوظ في قاعدة البيانات/الـ Store على النص المكتوب داخل الكود، وكأن الأداة قامت بتعديل النص داخل الكود المصدري نفسه.
  2. **إيقاف الـ Re-fetch العشوائي:** امنع إعادة تعيين حالة النصوص (State Reset) أثناء الـ Polling أو التنقل بين الصفحات الأربع المذكورة.
  3. **تفعيل زر (حفظ وتطبيق على الكل فوراً):** عند الضغط على هذا الزر، يتم حفظ القاموس الكامل للنصوص المعدلة في قاعدة البيانات (Cloudflare DB) وتحديث الـ Global State فوراً ليظهر النص الجديد بثبات تام عند جميع مستخدمي الموقع في نفس اللحظة بدون أي وميض أو رجوع للنص القديم.

---

### Task 4: تعديل زر (دعم فني) وإزالة التكرار من لوحة التحكم
- **المطلوب بالتفصيل:**
  1. **تغيير النص:** غير نص الزر من `دعم فني . تواصل مباشر واتساب` إلى:
     `دعم فني / Support`
  2. **تغيير اللون:** غير لون خلفية الزر إلى **الأسود أو الأسود الفاتح (Dark Charcoal / `#1f2937` أو `#111827`)** مع نص أبيض واضح وتأثير Hover مناسب.
  3. **إزالة التكرار في لوحة التحكم:** افحص كود `لوحة التحكم` (Dashboard Layout / Header / Sidebar) واحذف النسخة المكررة من زر الدعم الفني ليظهر **زر واحد فقط** في لوحة التحكم.

---

### Task 5: نظام الحظر الشامل (بالاسم + عنوان الـ IP) مع قائمة المحظورين وإلغاء الحظر
- **المطلوب بالتفصيل:**
  1. **التقاط وحفظ الـ IP:** عند تسجيل أي عضو أو دخوله للموقع، التقط عنوان الـ IP الخاص بجهازه (من الـ Request Headers في Cloudflare مثل `CF-Connecting-IP` أو `x-forwarded-for`) واحفظه في سجل المستخدم بقاعدة البيانات.
  2. **تنفيذ الحظر المزدوج (User + IP Ban):** عند قيام الأدمن بحظر شخص من لوحة التحكم أو قاعدة البيانات، يتم حظر **اسمه/حسابه بالإضافة إلى عنوان الـ IP الخاص بجهازه** في جدول/قائمة المحظورين (`banned_users` / `banned_ips`).
  3. **منع التسجيل مجدداً:** عند محاولة أي شخص فتح التسجيل أو إنشاء حساب جديد، افحص الـ IP الخاص به والاسم؛ إذا كان الـ IP محظوراً، ارفض عملية التسجيل فوراً وأظهر رسالة تمنعه من التسجيل.
  4. **واجهة إدارة المحظورين وفك الحظر (Unban):** أضف قسماً/جدولاً واضحاً في لوحة التحكم وقاعدة البيانات يعرض **قائمة الأشخاص المحظورين** (الاسم، الـ IP، تاريخ الحظر) مع زر **`إلغاء الحظر` (Unban)** بجانب كل شخص، والذي يقوم بحذف اسمه والـ IP الخاص به من قائمة الحظر ويعيد تفعيل صلاحية دخوله وتسجيله فوراً.
</tasks>
